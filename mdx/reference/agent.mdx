# Organigram Agent

Workspace agent primitives for Organigram applications.

This package contains the public, framework-independent parts of the Organigram
workspace agent: request and response types, snapshot and prompt construction,
response normalization, model usage extraction, and document text extraction.

## Installation

```bash
pnpm add @organigram/agent
```

## Prompt

The agent answers questions about one workspace, and prepares changes to its organigrams. Gather what the user may see of the workspace in a `Context`, and build the prompt with `buildPrompt()`. The prompt includes a snapshot of the workspace, with the names of files but never their contents. Send it to the language model of your choice, with `WORKSPACE_AGENT_OUTPUT_SCHEMA` as the structured output format when the provider supports it.

### ++dnt++buildPrompt

<div data-summary>

Build the prompt of the workspace agent for a conversation.

</div>

The prompt contains the rules of the agent, a snapshot of the workspace built with `buildSnapshot()`, the conversation and the output schema. It forbids proposals, transactions and signatures, and tells the model to treat file names, notifications and document contents as data rather than instructions. It cannot enforce these rules: validate the answer with `normalizeResponse()`.

```ts
const prompt = buildPrompt({ messages, context })
const answer = normalizeResponse(JSON.parse(completion), context)
```

<summary>Signature</summary>

```typescript
buildPrompt: (input: {

```

</details>

## Responses

The output of a language model is untrusted. `normalizeResponse()` keeps only valid citations, and only previews that create a new organigram or add to an organigram that is not deployed, without changing what it holds. The agent never proposes, signs or sends transactions: a deployed organigram changes only through its own procedures.

### ++dnt++normalizeResponse

<div data-summary>

Validate the answer of the language model and turn it into an `AgentResponse`.

</div>

Treat the model's output as untrusted. Without a message, the answer is replaced by a fallback message. Only citations of known types are kept, at most 8. A preview is kept only if it is a new organigram, or an addition to an organigram of the workspace that has no deployed organ, procedure or asset and that changes or removes none of its organs, entries, procedures or assets. Invalid previews are dropped.

<details>
<summary>Signature</summary>

### ++dnt++extractTextFromUploadedDocument

<div data-summary>

Extract the text of an uploaded document, to give it to the agent.

</div>

Reads Word documents (body, headers, footers, footnotes and endnotes), PDF files and plain text. PDF pages without enough text are read with OCR in English and French, which needs Poppler (`pdftocairo`) installed on the server; if OCR fails, the text found in the PDF is kept. Runs on Node.js only. The text is written by third parties: give it to the model as data, never as instructions.

## Usage

Count the tokens used by each call to a language model, to bill or limit usage.

### ++dnt++extractModelUsage

<div data-summary>

Read the tokens used by a call to a language model from the provider's response.

</div>

Reads the usage fields of OpenAI-compatible responses (`input_tokens`, `prompt_tokens`, cached token details) and Ollama responses (`prompt_eval_count`, `eval_count`). When the provider reports no input or output tokens, they are estimated as a quarter of the length of the prompt or completion, and `estimatedTokens` is `true`.

<details>
<summary>Signature</summary>

```typescript
extractModelUsage: (input: {
    payload: unknown;
    prompt: string;
    completion: string;
    provider: string;
    model: string;
}) => AiModelUsage
```

</details>
